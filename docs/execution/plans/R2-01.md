## Outcome and boundaries

A document's compiler, visible source symbols, external declarations, and origins must agree on one registered project, source set, and dependency generation. Two roots using different versions of the same FQN must remain independent regardless of registration, compilation, or query order. Production cannot see test-only sources or dependencies. Generated sources use the classpath of the source set that owns them.

Keep `ProjectContextImpl` as the project writer and `GrailsService` as composition root. Keep the existing bounded document/Gradle scheduling and request-lease mechanisms, extending their scope where necessary. Do not create a compiler per request or keystroke.

R2-02 retains the full dependency-refresh transaction across documentation/configuration/capabilities and same-coordinate replacement. R2-03 retains complete resolved project-edge propagation, composites, and renamed-project acceptance. R2-01 must preserve the identities and selected output paths needed by those tasks; it cannot merge modules or use guessed source edges as a shortcut. R2-04/05 retain general declaration/fallback and capability work. Any fallback that defeats an R2-01 isolation case must nevertheless be repaired here.

## Proposed state model and ownership

The following types are proposals to implement, not existing APIs. Prefer small immutable value objects over another framework.

| Value/state | Required contents | Owner and lifetime |
|---|---|---|
| `SourceSetModel` | Build-root identity, Gradle project path, module directory, actual source-set name, source roots with include/exclude rules, generated attribute when evidenced, ordered compile-classpath entries, output paths and completeness/errors | Immutable Gradle candidate copied into committed `GradleModel`; never mutable `DependencyNode` instances shared with an in-flight model |
| Scope identity | Registered root generation + build/project identity + source-set name + dependency membership revision | Created by project/model owner; removal/re-add must produce a different identity even at the same URI |
| `SourceSetCompilationState` | Compiler configuration, owned loader chain, compilation unit, source/error caches, input revisions and scoped derived state | Internal to `GrailsCompiler`, under `ProjectContextImpl`'s writer; created lazily on admitted background work |
| Scoped read generation | Matching snapshot/AST/index view, source-set membership, loader or unavailable state, discovery view, and scoped caches | Captured together through the project owner; retained only by the relevant bounded request/work leases |
| Discovery membership | Scope identity, ordered classpath identity, scan/result or immutable declarations, scan generation, cancellation and retirement state | Existing `DiscoveryService`, wired by `GrailsService`; instance-owned rather than an unowned static project-loader registry |

`generated` is an attribute of a source root, not a mutually exclusive source-set kind. Keep actual names such as `main`, `test`, and `integrationTest`. Do not infer arbitrary source-set visibility from its name. An unclassified or ambiguous file returns explicit unavailable/degraded analysis, with existing syntax/snippets still usable; it does not silently inherit `main` or the default project. Preserve GSP's existing project routing and record its explicit analysis mapping without claiming R4 embedded-language completion.

Use ordered value lists for classpaths. Equality must include entry order and scope/revision; an integer hash alone is not identity. Preserve local files/directories and artifacts lacking Maven coordinates. Keep shared immutable artifact caching optional: per-scope owned results are sufficient for this task. Do not share mutable ASTs, compilation units, reflection caches, or visibility lists as an optimization.

### 2. Export real Gradle source-set membership

1. Extend `GrailsProjectBuilder` to preserve each module's build identity, Gradle project path, and root. Stop flattening IDEA modules into one analytical project. Existing `IdeaProject` metadata can enrich labels/source attachments, but is not the authoritative compile-classpath list.
2. Add a versioned, extension-owned Gradle init-script resource and a narrow model reader under `core/gradle/`. Default transport: a transient export task invoked through the existing owned Tooling API connection. It exports evaluated source-set values into a uniquely owned output file, separate from Gradle logs; it does not edit the user's build scripts. Serialize only values, validate the schema and bound output size. Clean up only the exporter’s own temporary files on success, cancellation, and failure.
3. Export each actual source set's source membership and ordered `compileClasspath`, including output-directory entries and exclusions. Keep runtime/annotation-processor paths distinct; never implement compile scope as “all dependencies except TEST.” Preserve generated flags from exposed model metadata (including IDEA source-root metadata); when a producer does not classify a generated directory, retain its actual source membership and label that attribute unknown rather than inventing it from a pathname.
4. Run export in the existing bounded sync workflow with its wrapper, cancellation token, timeout, and connection ownership. Do not resolve models from a provider getter, silently fall back to another project's model, or run application/test/generator tasks during a read. Respect the existing workspace-trust execution boundary.
5. Add `SourceSetModel` values to `GrailsProject` and immutable `GradleModel`; update `ProjectContextImpl.toGradleModel`. Keep existing client DTO compatibility unless a necessary protocol change is separately covered by both-component checks. Update `ProjectCache`'s schema version and reject older cached models without membership.
6. Verify extraction on a pinned real Gradle fixture containing two modules, custom source paths, generated main/test roots, local-file dependencies, and a custom source set. Capture the actual export and expected ordering. A mocked `DependencyNode.scope` is not enough.

Gradle documents the compile classpath on [SourceSet](https://docs.gradle.org/current/javadoc/org/gradle/api/tasks/SourceSet.html) separately from runtime classpaths, and the generated flag on [IdeaSourceDirectory](https://docs.gradle.org/current/javadoc/org/gradle/tooling/model/idea/IdeaSourceDirectory.html). Use only APIs present in the repository's pinned Tooling API and fixture wrapper; these current documentation links do not establish version compatibility.

### 3. Route documents and related sources to one scope

1. Have the existing workspace discovery/registration flow register model modules separately with their owning workspace-root generation. Track which registrations a workspace folder owns so its removal invalidates its modules without deleting an independently registered nested root. Exact project graph propagation remains R2-03.
2. Reuse a single canonical, segment-aware routing policy for compiler and discovery. Choose the longest applicable registered module/root, then resolve source-set membership from the model's roots and inclusion rules. Cover Windows URI encoding/drive forms and case-sensitive filesystem behavior; do not lowercase every path.
3. Scope `FileContentTracker`'s derived FQN/dependency maps to the selected project/source set. Its URI-keyed open buffers may remain centrally owned. In `ServiceUtils` and compiler admission, reject related source files outside permitted membership instead of trusting an unscoped FQN lookup.
4. Keep output paths selected by Gradle as classpath entries. Do not infer a source dependency from matching module names or JAR paths. Unsupported or ambiguous membership is explicit and cannot grant wider visibility.

### 4. Isolate the entire compiler path

1. Inject the owning project's resolved input view into `GrailsCompiler`; replace every project-specific `grailsService.project` read in full/incremental compilation, compiler options, target paths, analysis phases, and discovery registration. Update initial construction, reactivation, and affected test doubles. Shared config/progress/error services remain explicit collaborators.
2. Use lazy `SourceSetCompilationState` instances under the existing project writer. Each scope has its own configuration, compilation unit, source/error caches and loader chain. Route all compile, source lookup, error retrieval, close/delete, invalidation, and snapshot-building operations through that scope; no mutable “last selected source set” used by concurrent readers.
3. Compile production and generated-production inputs with production visibility. Test analysis may consume main outputs or separately compiled private copies of allowed main inputs when required for unsaved-source analysis, but must not publish that test-context interpretation into the production snapshot. Verify unsaved main declarations remain visible to tests without permitting the reverse direction. Never reuse mutable production AST nodes in a test compilation unit.
4. Constrain application symbol resolution and discovery to the resolved classpath. Account for parent delegation: the server's own libraries/test harness must not become implicit project APIs. Preserve the supported JDK/Groovy compiler runtime without exposing arbitrary host dependencies. Prove this with both unique fixture APIs and a dependency deliberately present only in the server process.
5. Track every owned loader, including the URLClassLoader beneath a GroovyClassLoader. Reuse only equal scope/classpath generations. Retire old loaders and units through the lifecycle in slice 6, not immediate closure while readers still hold them. Apply `@CompileStatic` to changed/new production classes and fix the affected types.

### 5. Capture matching provider and discovery state

1. Extend the existing `ProjectContextImpl`/`RequestLease`/`RequestContext` boundary to capture scope, committed snapshot, classpath membership, loader, discovery view, and required caches from the same generation. Keep capture prompt; use retained facts or explicit unavailable state during construction/hibernation. Never activate or scan through `getClassLoaderForUri`.
2. Update `BaseProvider` to use this capture operation. Preserve `try/finally` lease release through the actual asynchronous provider work. Reconcile affected interfaces and test doubles; do not cast around missing scope contracts.
3. Scope `DiscoveryService` scans by membership generation, not project URI alone. Scan selected inputs instead of inheriting the whole server/system/application classpath. Resolve duplicate FQNs using the same ordered precedence as compilation and retain the selected artifact/path origin.
4. Migrate direct scan consumers, including `ImportStrategy` and `ClassNodeStrategy`, to the captured request discovery view. Audit calls with omitted/null URIs and reflection fallbacks: they may expose fixed language grammar where appropriate, but no other project's declarations.
5. Remove or scope package-only `CLASSNODE_CACHE` and loader-retaining method caches. Keep immutable grammar constants separate. Document owner, keys, count/byte bounds, invalidation, cancellation and disposal for each retained cache; propagate the configured resource budget across source sets rather than granting each one a new unbounded allowance.
6. Assert completion/import/hover signatures and declaration origins through real providers. A successful `loadClass` check alone does not prove IDE visibility.

### 6. Make scope retirement safe under concurrent work

1. Extend the existing root-removal path: remove routing and invalidate the scope generation immediately, reject new admissions, cancel queued work/scans, then drain active candidates and relevant reader leases asynchronously. Do not block the notification thread on scan/loader closure.
2. Build scan results privately. Before publication, compare registered root, source-set membership and scan generation. Superseded/removed candidates close their own result and cannot recreate membership. Old disposal callbacks must never clear a re-added root's new generation.
3. Release scans, loader chains, units, cache values and retained handles once their actual consumers finish or are cooperatively cancelled. A timeout is not permission to close a resource still in use. Keep retained safe index/model facts usable where the state contract requires them.
4. Cover hibernation, dependency-generation retirement, root removal, re-add and server shutdown. No owned static loader/FQN/cache path may retain retired membership. Preserve existing bounded queues; no unbounded `runAsync` scan-per-update replacement.
5. Use barriers to hold a scan and a provider request across removal/re-add. Verify the unrelated root still returns correct APIs, the old task cannot publish, and all old handles become releasable after drainage.
