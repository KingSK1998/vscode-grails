## Evidence brief before implementation

- Current behavior:
  - `FileContentTracker.didChangeFile` sorts `contentChanges` descending by `range.start` instead of applying them in array order to the text produced by the preceding edit (violating LSP 3.17 synchronization specification and failing sequential edits that depend on prior edit output).
  - `PositionHelper.getOffset` and `PositionHelper.getPosition` treat empty content `""` as invalid due to Groovy truth `!content` returning -1 or null, making incremental edits to empty files fail.
  - Document versions are tracked as raw integers without tracking `openGeneration`; if a document is closed and reopened, or reset to version 1/0, old candidates or obsolete versions could be accepted or confused with the new generation.
  - Obsolete versions (e.g. `version <= currentVersion` for the same open generation) are not rejected or ignored with a diagnostic warning; they can overwrite newer content if delivered out of order.
  - Candidate validation and diagnostics publication: diagnostics are published after releasing locks without passing or checking the document version / open generation, creating a race where slow compilation or delayed diagnostics can overwrite a newer buffer's state.
  - Deleting a file vs closing an overlay: `didDeleteFile` must remove both from tracking and disk index, whereas closing an overlay restores disk-backed facts.
- Failure/missing behavior and smallest reproducer:
  - Sequential incremental change array `[edit1, edit2]` applied in reverse order or out of order when sorted.
  - Empty file edit: insert text at `(0, 0)` fails with `Invalid offsets for change range: start=-1, end=-1`.
  - Reopen reset version: close file at version 5, reopen at version 1; version comparison fails if not generation-aware.
  - Delayed diagnostics publication race: edit to version 2 while version 1 finishes compile publishes version 1 diagnostics without checking if version 1 is still the active open generation / latest version.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-ID-001` (URI canonical), `INV-ID-005` (Position binding to revision), `INV-ID-010` (Open generation and version scoping), `INV-STATE-004` (No partial visibility), `INV-STATE-005` (Cancellation safe), `INV-STATE-007` (URI normalization), `INV-EDIT-001` (Protocol order and encoding).
- Unknowns and how this task will resolve them:
  - Audit and fix `FileContentTracker` change application, `PositionHelper` empty/CRLF/UTF-16 handling, `openGeneration` tracking in `TextFile` and `FileContentTracker`, candidate validation in `ProjectContextImpl`, and diagnostics versioning in `GrailsDiagnosticService`.

## Implementation decision

- Intended observable result; non-goals:
  - Incremental changes applied in exact order specified by LSP 3.17.
  - Empty text, CRLF, and UTF-16 surrogate pairs correctly handled by `PositionHelper` and `FileContentTracker`.
  - Monotonically increasing `openGeneration` assigned upon `didOpenFile`; obsolete versions (`version <= currentVersion` within same generation) rejected.
  - Candidate publication in `ProjectContextImpl` atomically verifies `openGeneration` and `version` before committing and publishing diagnostics.
  - Distinct handling for closing an overlay vs deleting a file.
  - Non-goals: Full multi-project classpath isolation (owned by R2-01).
- Files/owners to change:
  - `server/src/main/groovy/kingsk/grails/lsp/model/types/TextFile.groovy` (add openGeneration)

  - `server/src/main/groovy/kingsk/grails/lsp/utils/position/PositionHelper.groovy` (fix empty content handling, CRLF & UTF-16 surrogate character offsets)
  - `server/src/main/groovy/kingsk/grails/lsp/context/ProjectContextImpl.groovy` (generation and version validation before commit and diagnostics)
