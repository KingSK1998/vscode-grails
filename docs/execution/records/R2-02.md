## Implementation decision

- Intended observable result; non-goals:
  - Adding, removing, or modifying dependencies causes compiler, discovery ClassGraph, symbol caches, Groovydoc cache, MethodScope cache, and snapshot index to reflect the exact new dependency set without restart.
  - Changed artifact at same coordinates invalidates by content hash/fingerprint; unchanged artifacts are reused.
  - Failed/cancelled refresh preserves stale last-good state; simultaneous edits/removal cannot publish a mismatched candidate.
  - Non-goals: Cross-project edges and composite builds belong to R2-03.
- Files/owners changed:
  - `ArtifactFacts.groovy` & `ArtifactFactCache.groovy`: Thread-safe LRU cache (500 capacity, 1h TTL) extracting classes/packages keyed by SHA-256 fingerprint; accelerates content checks with `(length, lastModified)` fingerprint caching.
  - `ProjectCache.groovy`: Bumped version to 3; stores and verifies artifact content fingerprints; invalidates cache when any dependency artifact content changes or is deleted; watches `*.gradle.kts` and `*.toml` catalogs.
  - `DiscoveryService.groovy`: Returns `CompletableFuture<ScanResult>` from `updateClassGraph`; on scan publication, evicts method and classnode caches; safely closes superseded scans.
  - `GrailsCompiler.groovy`: `updateClassLoader()` locks `compileLock`, invalidates previous source set states and classloaders, resets error collector and incremental context, creates new isolated `GroovyClassLoader`s, and invokes `DiscoveryService.updateClassGraph`.
  - `ProjectContextImpl.groovy`: Implemented `applyDependencyUpdate(GrailsProject)` under writer lock, synchronizing compiler classloaders, replaying open buffers, clearing `groovydocCache`, `methodScopeCache`, cross-file caches, and committing atomic `VersionedSnapshot`; wired into `updateProject` and `triggerGradleSyncInternal`.
  - `GradleService.groovy`: Added explicit cancellation check before `cache.save(rootDir, project)` to discard cancelled builds and prevent poisoning binary cache.
- Input revision, candidate state, commit/publication and cancellation behavior:
  - Publication happens atomically under `ProjectContextImpl` writer lock.
  - If sync fails or is cancelled, `ProjectContextImpl` preserves existing state, sets `gradleSyncStale = true`, and rejects mismatched/late builds.
- Cache/resource impact, limits and invalidation:
  - Replaced classloaders and `ScanResult` instances are explicitly closed.
- Alternatives considered and evidence for the smallest sufficient change:
  - Direct atomic update in `ProjectContextImpl.applyDependencyUpdate` coordinates compiler, discovery, and snapshot without exposing partial state.
