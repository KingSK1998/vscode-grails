## Evidence brief before implementation

- Current behavior:
  - `GrailsInjectedStrategy` provides basic injection completions for services and artifact parameters based on naming conventions and basic heuristics, but uses hardcoded strings and loose AST casts.
  - `GrailsArtifactStrategy` generates artifact completion items (e.g., render, redirect, params, session) based on legacy static maps in `GrailsHelperIntegration` and `GrailsArtefactUtils`.
  - `ClosureDelegateStrategy` provides completions inside Grails closures (e.g. `mapping`, `constraints`), partially backed by static property maps in `GrailsHelperIntegration`.
  - `GspTagStrategy` looks up GSP tags, but TagLib namespace and method resolution lacks full provenance and capability scoping.
  - Dynamic GORM finders (e.g. `findBy<Property>`, `findAllBy<Property>And<Property>`, `countBy<Property>`) are partially handled or hardcoded in legacy utilities rather than expanded dynamically from domain properties with signature typing and negative scope protection.
- Failure/missing behavior and smallest reproducer:
  - Missing capability: If GORM is not on the classpath or a class is not an admitted GORM entity/trait, GORM dynamic finders/properties must not be invented.
  - Renamed or deleted domain property: If a property `title` is deleted or renamed to `headline`, `findByTitle` must disappear and `findByHeadline` must appear.
  - Injected conventions: Services and TagLibs injected into controllers must only be resolved if the corresponding service/TagLib actually exists in the project or its dependencies; unrelated projects or non-Grails classes must not receive injected properties.
  - Absence of capability adapters boundary: Currently, various strategies directly inspect AST or call static helpers without a unified `GrailsCapabilityAdapter` boundary declaring capability evidence, applicability, inputs, output derivation, invalidation, and fallback.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-DISC-001`: Scoped discovery — resolution respects project and source-set boundaries.
  - `INV-DISC-003`: Capability derivation — dynamic forms expand from actual domain model declarations, not hardcoded inventories.
  - `INV-STATE-003`: Invalidation on incremental compile / dependency refresh.
  - `INV-STATE-004`: AST read safety via `RequestContext.ast()`.
- Unknowns and how this task will resolve them:
  - GORM dynamic finder forms: What forms are supported? `findBy*`, `findAllBy*`, `countBy*`, `list*`. These must be dynamically derived from the domain class's properties (`PropertyNode` / `FieldNode`), generating typed parameters and return types.
  - Capability detection: How is GORM entity capability detected? By class location (under `grails-app/domain/`), `@Entity` / `grails.persistence.Entity` annotation, or GORM trait/base class (`grails.gorm.Entity`, `org.grails.datastore.gorm.GormEntity`).
  - Injection conventions: What Grails conventions exist?
    - Controllers: `params`, `request`, `response`, `session`, `flash`, `actionName`, `controllerName`, plus auto-injected services (`<serviceName>Service`).
    - TagLibs: namespaces (default `g`), tag methods receiving `(Map attrs, Closure body)` or `(Map attrs)`.
    - GORM Domains: dynamic finders, GORM instance methods (`save()`, `delete()`, `validate()`, `errors`), dynamic properties (`id`, `version`).
  - Negative cases: If GORM / Grails web dependency is missing or removed, capability adapters must return empty without fallback invention.

## Implementation decision

- Intended observable result; non-goals:
  - Observable result: Typed capability adapters (`GormCapabilityAdapter`, `GrailsInjectionCapabilityAdapter`, `TagLibCapabilityAdapter`) that expand dynamic members from AST entities with provenance (`ORIGIN_KIND = CAPABILITY_ADAPTER`), provide accurate parameters, return types, and documentation, and return empty when capabilities are missing.
  - Non-goals: Runtime application execution (adapters operate purely on static AST and resolved classpath evidence).
- Files/owners to change:
  - New capability adapter infrastructure under `kingsk.grails.lsp.core.capability`:
    - `GrailsCapabilityAdapter`: Interface declaring capability name, detection rule, inputs, derivation methods, and limits.
    - `GormCapabilityAdapter`: Dynamic finders (`findBy*`, `findAllBy*`, `countBy*`), GORM properties (`id`, `version`, `errors`), and static/instance methods based on domain properties.
    - `GrailsInjectionCapabilityAdapter`: Artifact-specific conventions (controller parameters/properties, service injection, TagLib namespace delegates).
    - `TagLibCapabilityAdapter`: Custom TagLib discovery and tag method completions.
  - Integration with `DiscoveryService` and completion strategies (`GrailsInjectedStrategy`, `PropertyExpressionStrategy`, `MethodCallExpressionStrategy`, etc.).
  - New specification suite: `server/src/test/groovy/kingsk/grails/lsp/capability/GrailsCapabilityAdapterSpec.groovy`.
- Cache/resource impact, limits and invalidation:
  - Adapters derive from `RequestContext` snapshot; no long-lived mutable AST state retained.
- Contract conflict/ADR update, if any: None; conforms to ADR-009, ADR-010, ADR-011.
