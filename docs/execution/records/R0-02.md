## Evidence brief before implementation

- Current behavior:
  - `GrailsLanguageServer.initialize` throws `ResponseErrorException` if `params.workspaceFolders` is empty or null, preventing zero-root workspaces.
  - `GrailsLanguageServer` does not implement `initialized` notification handler; workspace discovery was previously a commented-out TODO inside `initialize`.
  - `WorkspaceManager.getProjectForUri` falls back to `getDefaultProject()` for unmatched URIs (`match ?: getDefaultProject()`), violating the requirement that unmatched URIs do not inherit a default Grails project.
  - `WorkspaceManager` does not track root generations or in-flight discovery futures; removing or re-adding a root while discovery is blocked could allow late Gradle results to resurrect removed state.
  - `WorkspaceManager.getProjectForUri` uses simple `.startsWith` without directory boundary checking, allowing `D:\app-other` to match root `D:\app`.
  - `GrailsWorkspaceService.isBuildConfigurationFile` only checks `build.gradle`, `build.gradle.kts`, `settings.gradle`, `gradle.properties`, missing `settings.gradle.kts` and version catalogs (`libs.versions.toml`).
  - `ActivationManager.ts` file watcher only listens to `**/build.gradle`, missing Kotlin build files and version catalogs.
- Failure/missing behavior and smallest reproducer:
  - Calling `initialize` with empty workspace folders throws `ResponseError` with `InvalidParams`.
  - Calling `getProjectForUri` with an external or unrelated file URI returns `activeProjectUri` instead of `null`.
  - A late discovery completion after root removal adds the project back to `WorkspaceManager`.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-OWN-007`: Gradle sync exclusively owns `ProjectConnection`.
  - `INV-OWN-008`: Cross-project visibility.
  - `INV-STATE-005`: Cancellation-safe.
  - `INV-STATE-007`: URI normalization and boundary matching.
  - `INV-STATE-008`: Reactivation lock.
  - `INV-PERF-001`: Responsive startup, nonblocking discovery.
- Unknowns and how this task will resolve them:
  - Implement root generations and cancel/discard late results on removal/re-add.
  - Implement strict root boundary checking and return null for unmatched URIs.
  - Wire `replayTrackedDocuments` on discovery completion for matching open buffers.

## Implementation decision

- Intended observable result; non-goals:
  - `initialize` returns capabilities immediately for zero or multiple roots.
  - Discovery starts asynchronously after `initialized`.
  - In-flight discovery uses root generations; late results are discarded if generation changed or root removed.
  - Unmatched URIs return null without inheriting default project.
  - File replay only replays open buffers in the matching root; closed buffers are excluded.
  - Build-watch debounce covers Kotlin settings and version catalogs, unioning affected roots.
- Files/owners to change:
  - `server/src/main/groovy/kingsk/grails/lsp/GrailsLanguageServer.groovy`
  - `server/src/main/groovy/kingsk/grails/lsp/services/WorkspaceManager.groovy`
  - `server/src/main/groovy/kingsk/grails/lsp/services/GrailsWorkspaceService.groovy`
  - `server/src/main/groovy/kingsk/grails/lsp/services/GradleService.groovy`
  - `client/src/core/lifecycle/ActivationManager.ts`
  - `server/src/test/groovy/kingsk/grails/lsp/services/WorkspaceLifecycleSpec.groovy`
- Input revision, candidate state, commit/publication and cancellation behavior:
  - Discovery results published to `WorkspaceManager` only if root generation matches and not stopped.
- Cache/resource impact, limits and invalidation:
  - Disposed contexts cancel activation futures and clear snapshots.
