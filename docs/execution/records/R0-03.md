## Evidence brief before implementation

- Current behavior:
  - `GrailsLanguageServer.startGrailsLanguageServer` uses `LSPLauncher.createServerLauncher(server, inputStream, outputStream)`. This binds the remote client proxy interface to standard `org.eclipse.lsp4j.services.LanguageClient`.
  - In `GrailsService.connect`, the client is cast to `kingsk.grails.lsp.protocol.GrailsLanguageClient`. Because the dynamic proxy only implements `LanguageClient`, notifications such as `notifyAllProjects`, `projectUpdated`, etc. fail or are not properly dispatched as custom Grails protocol notifications.
  - In `WorkspaceManager`, when root discovery finishes and a project is discovered/added, `grailsService.notifyAllProjects()` is not called; `scripts/smoke-server.js` specifically waits for `grails/allProjects` notification from the server.
  - `logback.xml` routes all application logs to `STDERR` (`System.err`) and rolling file `logs/grails-language-server.log` with `<maxHistory>14</maxHistory>`. Stdout is reserved for framed LSP messages.
  - `LanguageServerManager.ts` registers handlers (`registerProgressHandler`, `registerMessageHandler`, `registerProjectsSyncHandlers`) before calling `await this.client.start()`.
  - In `GrailsLanguageServer.main`, after `startGrailsLanguageServer` completes or upon failure, `System.exit(...)` is not consistently called to ensure termination of any non-daemon threads or resources.
- Failure/missing behavior and smallest reproducer:
  - Starting the server and casting the launcher remote proxy to `GrailsLanguageClient` causes method missing or inability to dispatch `@JsonNotification("grails/allProjects")` over JSON-RPC.
  - Running `scripts/smoke-server.js` against the fat JAR times out or fails if `grails/allProjects` is never emitted.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-PERF-001`: Interactive callbacks/reads do not synchronously compile or scan libraries.
  - `INV-STATE-005`: Cancellation-safe.
  - `INV-STATE-006`: Explicit failure/degradation.
- Unknowns and how this task will resolve them:
  - Construct `LSPLauncher.Builder<GrailsLanguageClient>()` with `.setRemoteInterface(GrailsLanguageClient.class)` to bind the custom Grails client interface.
  - Emit `grailsService.notifyAllProjects()` on workspace root discovery completion, root initialization, and project removal.
  - Ensure clean exit on shutdown and failure in `GrailsLanguageServer.main`.
  - Rebuild shadow JAR (`npm run build:server`), copy via `npm run copy-server`, and verify using `scripts/smoke-server.js`.

## Implementation decision

- Intended observable result; non-goals:
  - Rebuilt JAR emits only framed JSON-RPC traffic on stdout.
  - Logs are confined to stderr and bounded rolling file.
  - `grails/allProjects` and `grails/projectUpdated` custom notifications are cleanly received by client over stdio.
  - Real smoke test (`scripts/smoke-server.js`) discovers test project, opens unsaved document, receives diagnostics and document symbols, and exits with code 0 without leaving orphaned processes.
- Files/owners to change:
  - `server/src/main/groovy/kingsk/grails/lsp/GrailsLanguageServer.groovy`
  - `server/src/main/groovy/kingsk/grails/lsp/GrailsService.groovy`
  - `server/src/main/groovy/kingsk/grails/lsp/services/WorkspaceManager.groovy`
- Input revision, candidate state, commit/publication and cancellation behavior:
  - Custom proxy created via LSPLauncher builder; bound directly before listening starts.
- Cache/resource impact, limits and invalidation:
  - Log retention strictly bounded to 14 days in `logback.xml`. Process clean termination on shutdown request.
