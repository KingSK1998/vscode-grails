## Evidence brief before implementation

- Current behavior:
  - `scripts/gradle.js` delegates to `gradlew.bat` (on win32) or `./gradlew` (on unix) with `cwd: server`.
  - `scripts/copy-server.js` copies the single fat JAR from `server/build/libs/grails-language-server-*-all.jar` to `client/server/grails-language-server-current-all.jar`. If `server/build/libs/` has zero or multiple fat JARs, it throws an error. However, `client/server/` retained a legacy `grails-language-server-0.4.1-SNAPSHOT-all.jar` from past builds.
  - `client/src/services/languageServer/serverConfig.ts` resolves the server JAR by looking for `grails-language-server-current-all.jar` first, with fallback to single `grails-language-server-*-all.jar`. It resolves Java using `config.javaHome` with fallback to `process.env.JAVA_HOME`. However, neither handled potential surrounding quotes in environment variables or user settings on Windows.
  - `package.json` had `"clean": "bash scripts/clean.sh"`, which failed on Windows systems without bash in PATH.
  - `scripts/package.sh`, `scripts/build.sh`, `scripts/build-client.sh`, `scripts/ci/validate.sh` contained legacy paths (`cd client; npm install` or outdated JAR names), whereas root `package.json` owns consolidated npm commands.
  - `scripts/run-gradlew.js` contained obsolete nondeterministic selection ("pick largest JAR") and was unreferenced.
  - `.vscodeignore` correctly excludes test files, sourcemaps (`*.map`), source files, and obsolete JARs (`client/server/*.jar` except `!client/server/grails-language-server-current-all.jar`).
- Failure/missing behavior and smallest reproducer:
  - `npm run clean` failed on Windows: `'bash' is not recognized as an internal or external command`.
  - Stale `client/server/grails-language-server-0.4.1-SNAPSHOT-all.jar` remained in working tree alongside `grails-language-server-current-all.jar`.
  - Quoted `JAVA_HOME` strings (e.g. `"C:\Program Files\Java\jdk-17"`) could cause `existsSync(command)` to fail.
  - `npm run bundle` CLI wrapper on Windows could fail silently or retain unbundled `tsc` output if invoked via npm cmd wrapper.
  - No automated test asserting the exact file entries and exclusion rules for packaged VSIX.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - Stable server artifact identity: `client/server/grails-language-server-current-all.jar`.
  - Clean reproducible packaging without accidental artifacts or debug logs.
- Unknowns and how this task will resolve them:
  - Create cross-platform `scripts/clean.js` and wire `package.json` `"clean": "node scripts/clean.js"`.
  - Implement `scripts/bundle.js` using `esbuild.buildSync` Node API for reliable cross-platform bundling of `client/out/extension.js` (~1018 KB standalone bundle).
  - Enhance `scripts/copy-server.js` to prune any legacy versioned JARs in `client/server/` so only `grails-language-server-current-all.jar` exists in the runtime destination.
  - Add quote-stripping and fallback tests for Java executable resolution in `serverConfig.ts` and `serverConfig.unit.test.ts`.
  - Add a dedicated package content verification test (`scripts/package.test.js`) and run as part of `npm run test:client`.
  - Test building, packaging (`npm run package`), installing the VSIX using `code --extensions-dir <tempDir> --install-extension vscode-gng-support.vsix`, and running the smoke fixture against the installed package.
  - Remove dead/obsolete scripts (`scripts/run-gradlew.js`) and align shell wrappers to invoke root npm scripts.
