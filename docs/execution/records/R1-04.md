## Evidence brief before implementation

- Current behavior:
  - `BaseProvider` and reader paths capture snapshot state, but provider implementations sometimes alternate between snapshot facts and live project context getters (`context.compiler`, `context.visitor`).
  - While `VersionedSnapshot` captures an `ASTAccessor` (the committed visitor instance), `ProjectIndex` and caches must be strictly verified against `INV-OWN-005` to ensure no `ASTNode` references are retained in value index structures.
  - Hibernation (`ProjectContextImpl.hibernate`) and disposal (`dispose`) nullify live compiler/visitor references, but snapshots held in `SnapshotManager` retain visitor references indefinitely. There is no explicit request lease / drain mechanism before memory release, meaning AST structures and ClassLoaders in retained snapshots cannot be reclaimed until soft references are cleared by full GC under heap pressure.
  - Cross-project operations: `propagateInvalidation` in `WorkspaceManager` iterates over dependent projects and marks them dirty. We must ensure no nested cross-project write locks are acquired that could deadlock with concurrent compilation.
  - Routing and read getters: `WorkspaceManager.getProjectForUri` and context getters must never synchronously trigger compiler reactivation or Gradle sync.
- Failure/missing behavior and smallest reproducer:
  - Concurrent read while compilation commits: reader querying snapshot during `commitSnapshotLocked` could observe tearing if snapshot is not swapped atomically or if caches are read after AST swap.
  - Hibernation memory retention: hibernating a project retains ASTClassNodes in snapshot history; needs lease tracking to safely detach or drain AST references while preserving usable index facts.
  - Deadlock potential: nested project lock acquisition if cross-project invalidation runs inside a project write lock.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-OWN-001` (Single writer: providers never write to compiler/visitor/tracker).
  - `INV-OWN-005` (AST boundary: ProjectIndex, SymbolInfo, MethodScopeCache retain no ASTNode references).
  - `INV-OWN-006` (Snapshot lineage ownership: SnapshotManager owns active, LKG, and max 3 history).
  - `INV-OWN-009` (Hibernation ownership: WorkspaceManager controls LRU hibernation).
  - `INV-STATE-001` (Single-writer principle).
  - `INV-STATE-002` (Read-never-write).
  - `INV-STATE-003` (Coherent invalidation: derived facts match inputs).
  - `INV-STATE-004` (No partial visibility: readers never observe half-built ASTs or indexes).
  - `INV-STATE-010` (Clean memory release on hibernation/disposal).
  - `INV-STATE-011` (Cross-project lock order).
- Unknowns and how this task will resolve them:
  - Audit all 21 providers and `BaseProvider` to guarantee snapshot-bound reads without live field alternation.
  - Implement request lease counter / reader lease in `ProjectContextImpl` to track active in-flight reads.
  - On hibernation, allow safe detach of heavy AST instances once active request leases drain, preserving lightweight index and model facts.
  - Verify that dirty propagation in `propagateInvalidation` executes outside project write locks.

## Implementation decision

- Intended observable result; non-goals:
  - Deterministic concurrent-read safety: readers never block on writes, never observe half-updated state, and read consistent generation snapshots.
  - Retained readers observe stable generation facts; no mutable AST references leak into index structures.
  - Request lease tracking allows active reads to complete while hibernation/disposal safely releases heavy compiler/visitor/classloader resources once leases drain.
  - Routing and getters do not block or trigger synchronous reactivation.
  - Non-goals: Full rewrite of AST storage or external persistent database.
